## 1. Goal & non-goals

### 1.1 Goal

A Windows desktop tool that takes **two pre-extracted Pi OS images** (one Master, one Slave) and writes them to **two SD cards** in a single guided session, while pre-configuring each card with a role-specific bundle that drives the AstromechOS first-boot provisioning (hostname, SSH access, master→slave keypair, hotspot bootstrap creds). The operator's interaction ends when the cards are flashed: from then on the AstromechOS first-boot stack (`software/scripts/firstboot_setup.sh` and downstream) brings both Pi 4Bs up to a fully paired state with **zero further manual config**.

### 1.2 Explicit non-goals

- **Image extraction from running Pi 4Bs** — the operator extracts images themselves (PiShrink + xz, Win32DiskImager, `dd`, etc.). The Imager only consumes the resulting files.
- **OS catalog / network download** — no online image repository, no telemetry, no analytics.
- **Cross-platform** — Windows-only for v1. The `platform/` layer is structured so Linux/macOS can be added later without touching `core/`.
- **Reinstalling AstromechOS from scratch** — the source images already contain a configured AstromechOS install; the Imager only flashes + injects per-pair config.
- **Beyond two cards per session** — the wizard handles exactly one Master + one Slave (or one of either in "single-role" mode). Bulk flashing of fleets is out of scope.

## 2. The AstromechOS first-boot contract

The companion AstromechOS scripts (`software/scripts/firstboot_setup.sh`) define a strict contract for files the Imager must place in the boot FAT32 partition of each SD card. The Imager **is the producer**; AstromechOS firstboot **is the consumer**.

### 2.1 Files written to `/boot/` (the FAT32 boot partition root)

| Path | Purpose | Source ref |
|---|---|---|
| `/ASTROMECH_FIRSTBOOT_READY` | Empty marker. Without it, firstboot_setup.sh does nothing. **Must be written LAST.** | `firstboot_setup.sh:67-72` |
| `/astromech_init.cfg` | INI-format bootstrap config. Sections: `[system]`, `[github]` (opt.), `[hotspot]`, `[slave]` (opt.) | `firstboot_setup.sh:80, 300-445, 451, lib_config.sh::cfg_get` |
| `/astromech_secrets/init_config.json` | `{role, hostname, imager_version, flashed_at}` | `firstboot_setup.sh:161-185` |
| `/astromech_secrets/authorized_keys` | OpenSSH public keys (one per line, trailing newline required for awk dedup) | `firstboot_setup.sh:124-141` |
| `/astromech_secrets/id_ed25519` | **Master only.** Outbound keypair private half. Mode 0600 re-applied by firstboot. | `firstboot_setup.sh:146-158` |
| `/astromech_secrets/id_ed25519.pub` | **Master only.** Same keypair public half. Mode 0644. | same |
| `/hw_layout.json` | Optional I2C HAT layout override (skips `detect_hats.py` scan on first boot) | `firstboot_setup.sh:237-262` |

### 2.2 Required `astromech_init.cfg` sections

```ini
# Generated by AstromechOS Imager <version> on <ISO8601 UTC>
# DO NOT EDIT — consumed and self-destructed on first boot.

[system]
user = pi                                    # install user (defaults: pi → astromech → artoo)

[github]                                     # optional — switch repo origin via DNA validation
repo_url = https://github.com/<fork>/AstromechOS.git
branch = main

[hotspot]                                    # bootstrap creds — IDENTICAL on master + slave
ssid = Astromech_Boot_3F2A                   # ^Astromech_Boot_[0-9A-F]{4,8}$
password = <32 hex chars>                    # WPA2-PSK 8-63 ASCII printable

[slave]                                      # optional — only emit when slave hostname is non-default
host = astromech-slave.local                 # how the Master finds the Slave via avahi (firstboot_setup.sh:355)
user = pi                                    # SSH user on the Slave; defaults to [system] user (firstboot_setup.sh:356)
```

### 2.3 Pair-level invariants

The Imager produces **two** boot partitions in a single session that must satisfy:

1. The `[hotspot]` block in `astromech_init.cfg` is **byte-identical** on master and slave.
2. The pubkey in master's `astromech_secrets/id_ed25519.pub` appears in slave's `astromech_secrets/authorized_keys`.
3. master's `init_config.json[role]` == `"master"`, slave's == `"slave"`.
4. Both `init_config.json[hostname]` values are RFC 1123–valid and distinct.

These invariants are checked by `assert_pair_symmetry()` after both flashes complete.

## 4. Wizard flow

Six steps, navigation via `QML StackView`. Shared state in a `WizardState` `QObject` singleton exposed to QML. Saved input never lost on Back.

```
[1] Mode      → [2] Images → [3] Storage → [4] Customize → [5] Confirm+Flash → [6] Done
  ↑________________________________________________|              cancel-disabled after _self_validate
```

### Step 1 — Mode

Three card buttons:
- **Flash both (recommended)** — normal new-pair build.
- **Master only** — slave SD broken / dome rework.
- **Slave only** — body SD broken / re-pair to existing master.

Mode determines which other steps activate role-specific UI.

### Step 2 — Images

One drop-or-browse zone per active role. Validation on select:
- Extension in `{.img, .img.xz, .img.gz, .zip}` (magic-byte verified, not just extension).
- File size ≥ 100 MB (sanity floor).
- `.zip` must contain exactly one `.img` entry; otherwise rejected with a clear message.
- Display detected format + best-effort **uncompressed size** (xz `--list` parse, gzip ISIZE footer, zip entry header, raw `stat.st_size`).

### Step 3 — Storage

Removable-drive list, refreshed every 2 s:

```
☐  E:  SanDisk Ultra 32 GB   \\.\PHYSICALDRIVE2   [Master target ▾]
☐  F:  Samsung Evo  32 GB    \\.\PHYSICALDRIVE3   [Slave target ▾]
```

Hard filters:
- `InterfaceType = 'USB'` AND `MediaType` contains `Removable` (WMI).
- Excluded: system drive (`%SystemDrive%`), drives ≥ 256 GB.
- Excluded with explanation: drives smaller than required uncompressed image size + 5 % margin.
- Refuses to proceed if master_target == slave_target.

Mode adaptation:
- 2 SDs detected + "Both" → parallel flash, user assigns role per row.
- 1 SD detected + "Both" → sequential mode armed; step 5 prompts "Insert slave SD now" between flashes.

### Step 4 — Customize

**Required**:
- `authorized_keys` — multi-line textarea or "Load `.pub` file" button. ≥ 1 valid OpenSSH pubkey line (regex see §6.5).

**Advanced (collapsed by default)**:
- Hostname overrides (defaults `astromech-master` / `astromech-slave`, RFC 1123 validated).
- Custom GitHub fork: `repo_url` (structural validation) + `branch` (refname rules).
- `hw_layout.json` (browse) — copied verbatim to the matching role's boot partition.
- Toggle **"Reuse ed25519 keypair from previous run"** — loads from `%APPDATA%\AstromechOS Imager\last_pair\`.
- Toggle **"Reuse hotspot bootstrap from previous run"** — loads from same dir.

**Read-only info line**:
```
✓ Fresh hotspot bootstrap will be generated
  SSID: (auto, ex. Astromech_Boot_3F2A · uppercase hex)
  PSK : (auto, 32-char random hex · WPA2-PSK)
```

### Step 5 — Confirm + Flash

Single screen, two phases:

**Phase A — summary table** (pre-click WRITE):

| Role | Image | Decompressed | Target | Hostname |
|---|---|---|---|---|
| Master | master-2026-05-20.img.xz | 6.2 GB | E: SanDisk 32 GB | astromech-master |
| Slave | slave-2026-05-20.img.xz | 4.8 GB | F: Samsung 32 GB | astromech-slave |

Red **WRITE** button with confirmation modal ("Erase E: and F: — Yes, I'm sure").

**Phase B — progress** (post-click, same screen):
- 1 or 2 progress bars labeled **decompress · write · verify · customize**.
- ETA + throughput MB/s per bar.
- Cancel active until immediately after `_self_validate`. After that, the trigger marker is being written in microseconds and cancel is hidden.

For sequential mode (1 reader, 2 cards): phase B flashes the first card, then prompts "Insert slave SD now"; the Imager waits for a new drive matching expected size, then flashes the second.

### Step 6 — Done

```
✓ Master flashed to E:  (SHA256 verified · firstboot bundle written)
✓ Slave  flashed to F:  (SHA256 verified · firstboot bundle written)

Hotspot bootstrap (Slave joins this until Master pushes its final SSID)
   SSID: Astromech_Boot_3F2A
   PSK : ●●●●●●●●●●●●●●●●  [Show 30s] [Copy]
   Stored at %APPDATA%\AstromechOS Imager\sessions\<id>\hotspot.json
   (current-user only NTFS ACL, auto-purged after 30 days)

Next steps:
   1. Eject both SDs (auto-eject already attempted)
   2. Insert into respective Pi 4B (Master in dome, Slave in body)
   3. First boot takes ~3 min and reboots automatically
   4. SSH available at astromech-master.local / astromech-slave.local

Log: %APPDATA%\AstromechOS Imager\logs\flash-2026-05-29T02-15-00.log
```

Buttons: **Flash another** (resets state → step 1), **Quit**.

### Navigation rules

- `Back` disabled once phase B of step 5 has produced any write.
- `Next` disabled while step validation fails.
- No `Enter = Next` accelerator on step 5 (safety: avoid accidental flash).
- All saved input persists in `WizardState`; Back never loses data.

## 5. Disk I/O & flash engine (Windows)

All Win32-specific code lives behind `core.IPlatformIO` (Protocol). Concrete impl: `platform/windows.py`.

### 5.1 Drive enumeration

WMI via `pywin32`:

```sql
SELECT DeviceID, Size, Model, SerialNumber, InterfaceType, MediaType
FROM Win32_DiskDrive
WHERE InterfaceType = 'USB' OR MediaType = 'Removable Media'
```

Joined to `Win32_DiskDriveToDiskPartition` → `Win32_LogicalDiskToPartition` → `Win32_LogicalDisk` for drive letters.

Belt-and-suspenders safety: never display drives matching `%SystemDrive%`, never display drives > 256 GB, never display non-removable disks.

Refresh: 2 s poll in MVP. Post-MVP: `RegisterDeviceNotification` on `GUID_DEVINTERFACE_DISK`.

### 5.2 Lock & dismount

Before opening `\\.\PhysicalDriveN` for write:

```
for each volume V on the physical drive:
    h = CreateFileW("\\\\.\\<V>:", GENERIC_READ|GENERIC_WRITE,
                    FILE_SHARE_READ|FILE_SHARE_WRITE, OPEN_EXISTING)
    DeviceIoControl(h, FSCTL_LOCK_VOLUME)         # 3 retries, 500 ms backoff
    DeviceIoControl(h, FSCTL_DISMOUNT_VOLUME)
    # handle kept open for the duration of write — release lock on CloseHandle
```

If `FSCTL_LOCK_VOLUME` ultimately fails: `DriveLockError` with hint "close Explorer windows / antivirus scan".

### 5.3 Raw write

```python
h = CreateFileW(r"\\.\PHYSICALDRIVE2",
                GENERIC_READ | GENERIC_WRITE,
                FILE_SHARE_READ | FILE_SHARE_WRITE,
                None, OPEN_EXISTING,
                FILE_FLAG_NO_BUFFERING | FILE_FLAG_WRITE_THROUGH, None)
```

`FILE_FLAG_NO_BUFFERING` requires sector-aligned writes — sector size queried via `IOCTL_DISK_GET_DRIVE_GEOMETRY_EX`. Buffer size: **1 MB** (multiple of 4096, sweet spot between throughput and UI responsiveness).

**Producer-consumer pipeline** (2 threads per active FlashWorker):

```
[ImageSource]──decompress──▶ Queue(maxsize=4×1MB) ──▶ [DiskWriter]──WriteFile──▶ SD
       │                                                    │
       └──── SHA256 source running ────┐                    └── progress(bytes)
                                       ▼
                                   source_hash
```

Decompressor releases GIL during `lzma.decompress` → real parallelism with the writer. Queue acts as backpressure.

After last write:
```
FlushFileBuffers(h)
DeviceIoControl(h, IOCTL_DISK_UPDATE_PROPERTIES)
```

### 5.4 Streaming format support

`core/imagesource.py` exposes a `open_image(path) → ImageSource` factory that dispatches by magic bytes (with extension as tie-breaker):

| Magic | Source |
|---|---|
| `fd 37 7a 58 5a 00` | `XzSource` (stdlib `lzma`) |
| `1f 8b` | `GzSource` (stdlib `gzip`) |
| `PK\x03\x04` | `ZipSource` (stdlib `zipfile`, exactly 1 `.img` entry) |
| (none / MBR signature `55 AA` at offset 510) | `RawSource` (passthrough) |

Each source exposes `__iter__()` (yields 1 MB chunks), `uncompressed_size: int | None`, and context-manager cleanup.

### 5.5 Read-back verify

**Always enabled** by default (`--no-verify` CLI flag exists but discouraged). Source hash computed during decompression (no second pass over source). Read-back loop:

```python
hasher = sha256()
remaining = bytes_written
while remaining > 0:
    chunk = ReadFile(h_dev, min(remaining, 1MB))
    hasher.update(chunk)
    remaining -= len(chunk)
    progress.emit(...)
if hasher.digest() != source_hash:
    raise HashMismatchError(first_diff_offset=_locate_first_diff(...))
```

### 5.6 Boot partition access (two-path strategy)

**Primary (β): pyfatfs on raw device.**

```python
boot_part = find_boot_partition(r"\\.\PHYSICALDRIVE2")   # parse MBR/GPT, find 1st FAT32
with pyfatfs.PyFatFS(filename=device_path,
                     offset=boot_part.offset,
                     size=boot_part.size) as fs:
    fs.makedirs("/astromech_secrets", exist_ok=True)
    fs.writebytes("/astromech_secrets/init_config.json", json_bytes)
    ...
```

Advantages: deterministic, no auto-mount dependency.

**Fallback (α): drive letter after Windows remount.**

```python
letter = wait_for_new_drive_letter(timeout_s=30)         # poll GetLogicalDrives
boot_root = pathlib.Path(f"{letter}:\\")
(boot_root / "astromech_secrets").mkdir(exist_ok=True)
(boot_root / "astromech_secrets" / "init_config.json").write_bytes(json_bytes)
```

Both paths satisfy the same `BootPartition` interface (`write_bytes`, `read_bytes`, `mkdir`, `exists`). `customization.py` is path-agnostic.

**FAT32 perms note**: `chmod 0700` on `astromech_secrets/` is documented in the contract but ignored at the FAT32 level. `firstboot_setup.sh` re-applies permissions during step 1 on the Pi side.

### 5.7 Admin elevation

PyInstaller `.spec` embeds `requestedExecutionLevel level="requireAdministrator"` in the manifest. CLI startup:

```python
if platform.system() == "Windows" and not ctypes.windll.shell32.IsUserAnAdmin():
    ctypes.windll.shell32.ShellExecuteW(None, "runas", sys.executable,
                                         " ".join(sys.argv), None, 1)
    sys.exit(0)
```

### 5.8 Threading & cancellation

- Parallel (2 SDs): 1 UI thread + 2 × FlashWorker (`QThread`) — each worker runs producer + consumer = 5 threads total.
- Sequential: 1 FlashWorker active at a time.
- Cancellation: `threading.Event` shared inside a FlashWorker. Checked at every loop iteration. Effect by phase: see §7.5.

### 5.9 Eject

`DeviceIoControl(h, IOCTL_STORAGE_EJECT_MEDIA)` — best-effort. On failure: `EjectFailedError` (warning), prompt user to safe-eject manually.

## 6. Firstboot bundle (customization)

### 6.1 Data model

```python
class Role(Enum):
    MASTER = "master"
    SLAVE = "slave"

@dataclass(frozen=True)
class HotspotBootstrap:
    ssid: str          # ^Astromech_Boot_[0-9A-F]{4,8}$, ≤ 32 bytes UTF-8
    password: str      # WPA2-PSK 8–63 ASCII printable

@dataclass(frozen=True)
class Ed25519Pair:
    private_openssh: bytes   # for /astromech_secrets/id_ed25519
    public_openssh: bytes    # for /astromech_secrets/id_ed25519.pub (with trailing \n)

@dataclass(frozen=True)
class FirstbootConfig:
    authorized_keys: list[str]                 # ≥1 valid OpenSSH pubkey line
    install_user: str = "pi"
    repo_url: str | None = None
    repo_branch: str = "main"
    hostname_master: str = "astromech-master"
    hostname_slave: str = "astromech-slave"
    hw_layout_master: Path | None = None
    hw_layout_slave: Path | None = None
    hotspot_bootstrap: HotspotBootstrap | None = None    # auto-generated by orchestrator if None
    # Auto-managed by the orchestrator — NOT user input. Empty defaults exist
    # only to keep the dataclass instantiable in unit tests; production code
    # must always set them before passing to FirstbootBundle.
    imager_version: str = ""                             # e.g. "0.1.0"
    flashed_at_iso: str = ""                             # e.g. "2026-05-29T02:15:00Z"

    def __post_init__(self):
        _validate_authorized_keys(self.authorized_keys)
        _validate_hostname(self.hostname_master)
        _validate_hostname(self.hostname_slave)
        _validate_install_user(self.install_user)
        if self.repo_url is not None:
            _validate_repo_url(self.repo_url)
            _validate_branch_name(self.repo_branch)
        if self.hotspot_bootstrap is not None:
            _validate_ssid(self.hotspot_bootstrap.ssid)
            _validate_wpa2_psk(self.hotspot_bootstrap.password)
```

### 6.2 Cryptographic generators

```python
# keygen.py
def generate_ed25519(comment="astromech-master@imager") -> Ed25519Pair:
    sk = Ed25519PrivateKey.generate()
    priv = sk.private_bytes(Encoding.PEM, PrivateFormat.OpenSSH, NoEncryption())
    pub = sk.public_key().public_bytes(Encoding.OpenSSH, PublicFormat.OpenSSH)
    return Ed25519Pair(priv, pub + b" " + comment.encode() + b"\n")

def generate_hotspot_bootstrap() -> HotspotBootstrap:
    suffix = secrets.token_hex(2).upper()              # 4 hex chars
    return HotspotBootstrap(
        ssid=f"Astromech_Boot_{suffix}",
        password=secrets.token_hex(16),                # 32 hex = 128-bit entropy
    )
```

Persistence in `%APPDATA%\AstromechOS Imager\last_pair\` (DACL: current user only). Saved **only after** successful verify+customize for both SDs.

### 6.3 Renderers

```python
def render_init_cfg(cfg: FirstbootConfig) -> bytes:
    """Generates /astromech_init.cfg. Refs firstboot_setup.sh:80, 304."""
    lines = [
        f"# Generated by AstromechOS Imager {cfg.imager_version} on {cfg.flashed_at_iso}",
        "# DO NOT EDIT — consumed and self-destructed on first boot.",
        "",
        "[system]",
        f"user = {cfg.install_user}",
    ]
    if cfg.repo_url:
        lines += ["", "[github]",
                  f"repo_url = {cfg.repo_url}",
                  f"branch = {cfg.repo_branch}"]
    if cfg.hotspot_bootstrap is not None:
        # Refs firstboot_setup.sh:325-326 — keys are EXACTLY "ssid" and "password"
        lines += ["", "[hotspot]",
                  f"ssid = {cfg.hotspot_bootstrap.ssid}",
                  f"password = {cfg.hotspot_bootstrap.password}"]
    # [slave] section: only emit when the slave hostname diverges from the default.
    # Default "astromech-slave.local" is already what firstboot_setup.sh:355 falls
    # back to, so emitting it would be no-op noise. Refs firstboot_setup.sh:355-356.
    if cfg.hostname_slave != "astromech-slave":
        lines += ["", "[slave]",
                  f"host = {cfg.hostname_slave}.local"]
    return ("\n".join(lines) + "\n").encode("utf-8")

def render_init_config_json(cfg: FirstbootConfig, role: Role) -> bytes:
    """Generates /astromech_secrets/init_config.json. Refs firstboot_setup.sh:161-185."""
    obj = {
        "role": role.value,
        "hostname": cfg.hostname_master if role is Role.MASTER else cfg.hostname_slave,
        "imager_version": cfg.imager_version,
        "flashed_at": cfg.flashed_at_iso,
    }
    return (json.dumps(obj, indent=2) + "\n").encode("utf-8")

def render_authorized_keys(cfg: FirstbootConfig, role: Role,
                            master_pub: bytes | None) -> bytes:
    """Generates /astromech_secrets/authorized_keys. Refs firstboot_setup.sh:124-141."""
    keys = [k.strip() for k in cfg.authorized_keys]
    if role is Role.SLAVE and master_pub is not None:
        keys.append(master_pub.decode("ascii").strip())   # slave inherits master pub
    return ("\n".join(keys) + "\n").encode("utf-8")       # trailing \n required by awk 'NF'
```

### 6.4 Orchestration

```python
class FirstbootBundle:
    def __init__(self, cfg: FirstbootConfig, master_pair: Ed25519Pair):
        self.cfg = cfg
        self.master_pair = master_pair

    def write_to(self, bp: BootPartition, role: Role) -> None:
        # 1. Secrets dir (mode 0700 ignored on FAT32; firstboot re-applies)
        bp.mkdir("/astromech_secrets")
        # 2. init_config.json
        bp.write_bytes("/astromech_secrets/init_config.json",
                       render_init_config_json(self.cfg, role))
        # 3. authorized_keys (slave gets master pub appended)
        master_pub = self.master_pair.public_openssh
        bp.write_bytes("/astromech_secrets/authorized_keys",
                       render_authorized_keys(self.cfg, role, master_pub))
        # 4. id_ed25519 keypair (MASTER ONLY) — refs firstboot_setup.sh:146-158
        if role is Role.MASTER:
            bp.write_bytes("/astromech_secrets/id_ed25519",
                           self.master_pair.private_openssh)
            bp.write_bytes("/astromech_secrets/id_ed25519.pub", master_pub)
        # 5. astromech_init.cfg
        bp.write_bytes("/astromech_init.cfg", render_init_cfg(self.cfg))
        # 6. hw_layout.json (optional) — refs firstboot_setup.sh:253-262
        hw = self.cfg.hw_layout_master if role is Role.MASTER else self.cfg.hw_layout_slave
        if hw is not None:
            bp.write_bytes("/hw_layout.json", hw.read_bytes())
        # 7. Self-validate before trigger
        self._self_validate(bp, role)
        # 8. Trigger marker LAST — refs firstboot_setup.sh:67-72
        bp.write_bytes("/ASTROMECH_FIRSTBOOT_READY", b"")

    def _self_validate(self, bp, role):
        cfg = json.loads(bp.read_bytes("/astromech_secrets/init_config.json"))
        assert cfg["role"] in ("master", "slave")
        _validate_hostname(cfg["hostname"])
        keys = bp.read_bytes("/astromech_secrets/authorized_keys").decode().splitlines()
        assert any(_OPENSSH_PUBKEY_RE.match(k.strip()) for k in keys)
        if role is Role.MASTER:
            assert bp.exists("/astromech_secrets/id_ed25519")
            assert bp.exists("/astromech_secrets/id_ed25519.pub")
        if role is Role.SLAVE:
            master_pub_line = self.master_pair.public_openssh.decode().strip()
            assert any(master_pub_line in k for k in keys), \
                "Slave authorized_keys missing master pubkey — master→slave SSH will fail"
        if self.cfg.hotspot_bootstrap is not None:
            init_cfg_text = bp.read_bytes("/astromech_init.cfg").decode("utf-8")
            assert f"ssid = {self.cfg.hotspot_bootstrap.ssid}" in init_cfg_text
            assert f"password = {self.cfg.hotspot_bootstrap.password}" in init_cfg_text


def assert_pair_symmetry(master_bp: BootPartition, slave_bp: BootPartition) -> None:
    """Verifies §2.3 invariants after both flashes complete."""
    m_hot = _extract_section(master_bp.read_bytes("/astromech_init.cfg"), "hotspot")
    s_hot = _extract_section(slave_bp.read_bytes("/astromech_init.cfg"), "hotspot")
    if m_hot != s_hot:
        raise PairAsymmetryError("master/slave [hotspot] block mismatch")
```

### 6.5 Validators (regexes match firstboot_setup.sh strictly)

| Field | Regex | Source |
|---|---|---|
| Hostname | `^[a-zA-Z0-9](?:-?[a-zA-Z0-9])*$`, len ≤ 63 | firstboot_setup.sh:206 |
| OpenSSH pubkey | `^(?:ssh-(?:rsa|ed25519|dss)|ecdsa-sha2-nistp(?:256|384|521)|sk-(?:ssh-ed25519|ecdsa-sha2-nistp256)@openssh\.com)\s+[A-Za-z0-9+/=]+(?:\s+.+)?$` | OpenSSH manpage |

| Branch name | git refname rules (simplified) | git refs |
| SSID bootstrap | `^Astromech_Boot_[0-9A-F]{4,8}$`, ≤ 32 bytes UTF-8 | this spec §2.2 |

## 7. Error handling & logging

### 7.1 Error taxonomy (core/errors.py)

```python
class ImagerError(Exception):
    severity: Literal["ERROR", "WARNING"]
    sd_state: Literal["SAFE", "GARBAGE", "UNCERTAIN", "BOOTABLE_NO_FIRSTBOOT", "OK"]
    retryable: bool
    recovery_hint: str

class PreflightError(ImagerError):       sd_state = "SAFE"
class ImageFormatError(PreflightError): ...
class ImageTooLargeError(PreflightError): ...
class DriveNotFoundError(PreflightError): ...
class DrivePermissionError(PreflightError): ...
class DriveLockError(PreflightError): ...
class ConfigValidationError(PreflightError): ...

class FlashError(ImagerError):           sd_state = "GARBAGE"; retryable = True
class DecompressError(FlashError): ...
class WriteError(FlashError): ...
class DriveDisconnectedError(FlashError): ...

class VerifyError(ImagerError):          sd_state = "UNCERTAIN"; retryable = True
class HashMismatchError(VerifyError): ...
class ReadbackError(VerifyError): ...

class CustomizationError(ImagerError):   sd_state = "BOOTABLE_NO_FIRSTBOOT"
class BootPartitionMountError(CustomizationError): ...
class BootPartitionWriteError(CustomizationError): ...
class BundleSelfValidationFailedError(CustomizationError): ...
class PairAsymmetryError(CustomizationError): ...

class CleanupError(ImagerError):         severity = "WARNING"; sd_state = "OK"
class EjectFailedError(CleanupError): ...
```

### 7.2 SD state → user message matrix

| `sd_state` | Dialog color | Message template |
|---|---|---|
| `SAFE` | blue (info) | "Nothing written. Fix X and retry." |
| `GARBAGE` | red | "Drive E: contains partial data — not bootable. Re-flash from scratch." |
| `UNCERTAIN` | orange | "Drive E: was fully written but content differs from source. Likely defective SD or reader. Try another SD." |
| `BOOTABLE_NO_FIRSTBOOT` | orange | "OS image valid but firstboot bundle incomplete. Pi will boot but won't auto-configure. Re-flash recommended." |
| `OK` | yellow (warning) | "Auto-eject failed. Use 'Safely Remove Hardware' before unplugging." |

### 7.3 Logging architecture

**A — Persistent JSON-lines** at `%APPDATA%\AstromechOS Imager\logs\flash-<ISO8601>.log`. UTC timestamps with ms. Rotate: keep last 20, delete older on startup.

```jsonl
{"ts":"2026-05-29T02:15:01.234Z","lvl":"INFO","mod":"diskwriter","msg":"Locked volume E:","ctx":{"phys_drive":2}}
{"ts":"2026-05-29T02:18:43.891Z","lvl":"ERROR","mod":"diskwriter","msg":"WriteFile failed at offset 4842225664","ctx":{"win32_err":1117,"err_class":"WriteError","sd_state":"GARBAGE"}}
```

**B — In-memory ring buffer** (1000 events), surfaced by *Help → Show recent log*.

### 7.4 Redaction (logging.Filter)

Never logged:
- ed25519 private → `<redacted: ed25519 private, fp=SHA256:...>`
- authorized_keys content → `<N keys, fingerprints: SHA256:abc..., ...>`
- WPA2 PSK → `<redacted: WPA2-PSK, fp=SHA256:abc...>` (SSID is fine; broadcast in air)
- `bytes` > 256 → `<N bytes>`
- Image file full paths → basename only

### 7.5 Cancellation effect by phase

| Phase at cancel | Worker action | Final SD state | User message |
|---|---|---|---|
| Decompress + write | Break loop, close handles | `GARBAGE` | "Cancelled. Drive E: not bootable, re-flash when ready." |
| Verify | Stop read-back, **proceed to customize anyway** | `UNCERTAIN` but image written | "Verify cancelled — integrity unconfirmed. Bundle written anyway. Re-flash recommended if in doubt." |
| Customize (before trigger) | Skip remaining writes, **DO NOT write trigger** | `BOOTABLE_NO_FIRSTBOOT` | "Cancelled mid-config. Pi boots but won't auto-configure. Re-flash recommended." |
| Customize (after trigger) | N/A — microsecond window | `OK` | (cancel impossible) |

### 7.6 Retry policy

| Operation | Retries | Backoff | Final failure |
|---|---|---|---|
| `FSCTL_LOCK_VOLUME` | 3 | 500 ms | `DriveLockError` |
| `WriteFile` 1 MB chunk | 0 | — | `WriteError` (hardware) |
| Open `\\.\PHYSICALDRIVEn` | 2 | 1 s | `DriveDisconnectedError` |
| pyfatfs mount | 1 | — | Fall back to α drive-letter |
| Drive letter poll (α) | 30 s @ 250 ms | — | `BootPartitionMountError` |
| `IOCTL_STORAGE_EJECT_MEDIA` | 1 | — | `EjectFailedError` (warning) |

### 7.7 Error dialog component

Single `ErrorDialog.qml`, reused everywhere. Always shows: typed-name title (human form), 1–2 line message, recovery hint, [Show details] (last 50 log lines + traceback), [Copy log path], [Export diagnostic]. `[Retry]` shown only when `retryable=True` AND phase=preflight. No modal-on-modal during flash — error replaces progress view.

### 7.8 Diagnostic bundle export

ZIP at user request: session log, system_info.json, wmi_dump.json (drive serials masked except last 4 chars), traceback.txt, redacted `firstboot_config.json`. **Never auto-uploaded.** PSK fingerprint included by default; full PSK opt-in checkbox for support escalation.

### 7.9 Crash safety

`sys.excepthook` + `qInstallMessageHandler` in `ui/app.py` catches unhandled exceptions: log CRITICAL with traceback, show last-resort dialog with diagnostic bundle path and GitHub issue link, button to open log directory in Explorer. CLI uses same hook, exit code 2.

### 7.10 Telemetry

**None.** Differentiating feature vs upstream rpi-imager. Documented in README.

## 9. AstromechOS-side contract (landed)

The `[hotspot]` bootstrap mechanism is **sealed on both sides as of 2026-05-29**. The shipped implementation lives in `software/scripts/firstboot_setup.sh` Section 4.7 (lines 300-445).

What the Pi side does on first boot when `[hotspot]` is present:

1. **Reads** `[hotspot] ssid` and `[hotspot] password` from `/boot/astromech_init.cfg` (lines 325-326).
2. **Master role**: invokes `setup_master_network.sh --non-interactive --ssid X --psk Y` to bring up `wlan0` as AP at the bootstrap SSID. Waits up to 5 minutes for the Slave at `[slave] host` (default `astromech-slave.local`) reachable + SSH key-based auth working.
3. **Master role**: once Slave reachable, generates `FINAL_SSID` via `gen_hotspot_ssid.sh` (CPU serial → `Astromech_Control_<XXXX>`). Pushes `(FINAL_SSID, BOOT_PSK)` to the Slave's `astromech-master-hotspot` nmcli profile over SSH (mirrors the `_push_slave_hotspot_creds` semantics from the Flask settings endpoint).
4. **Master role**: flips its own `astromech-hotspot` profile to `FINAL_SSID` via nmcli, persists to `master/config/local.cfg [hotspot]` ssid/password.
5. **Slave role**: invokes `setup_slave_network.sh --non-interactive --ssid X --psk Y` to add an `astromech-master-hotspot` profile pointing at the bootstrap SSID. The Master's SSH push from step 3 rewrites this profile to the final SSID before the Master flips its AP, so nmcli autoconnect transparently rejoins.

If `[hotspot]` is absent: Section 4.7 logs *"Hotspot bootstrap skipped: no [hotspot] in astromech_init.cfg"* and falls through to the legacy interactive `setup_*_network.sh` path. The Imager opting out of `[hotspot]` (e.g., a future flag) remains a supported degraded mode.

Contract surface frozen for the Imager:

| Section | Key | Default | Required when |
|---|---|---|---|
| `[hotspot]` | `ssid` | (none, opts out) | `Flash both` mode |
| `[hotspot]` | `password` | (none, opts out) | `Flash both` mode |
| `[slave]` | `host` | `astromech-slave.local` | `hostname_slave` is non-default |
| `[slave]` | `user` | `[system] user` | always derivable; Imager does NOT emit (default suffices) |

## 11. Glossary

| Term | Meaning |
|---|---|
| **Imager** | This tool (`astromechos_imager`) |
| **Pair** | One Master + one Slave SD card produced by the same session |
| **Bootstrap creds** | The temporary `Astromech_Boot_<XXXX>` SSID/PSK pair used during first boot, before Master takes over with its CPU-Serial-derived definitive SSID |
| **Firstboot bundle** | The set of files written by the Imager to a card's boot partition (`/ASTROMECH_FIRSTBOOT_READY`, `/astromech_init.cfg`, `/astromech_secrets/*`, optional `/hw_layout.json`) |
| **Trigger marker** | `/ASTROMECH_FIRSTBOOT_READY`. Empty file. Without it, `firstboot_setup.sh` does nothing. Imager writes this LAST in every flash. |
| **Pair symmetry** | The invariants of §2.3, asserted by `assert_pair_symmetry()` after both cards flashed |
| **DNA validation** | The paternity check `dna_validate` performs on a custom GitHub fork URL on the Pi side (firstboot_setup.sh:312) before swapping origin |
